02. Throughput is not responsiveness

At higher concurrency, combined throughput improves while some requests wait much longer for their first token.

Fixed-output concurrency sweep

512 generated tokens/request · greedy · reasoning OFF · one GB10 · no application tool calls.

8 streams: 110.8 aggregate tok/s8 streams: 0.30s worst TTFT32 streams: 83.32s worst TTFT
The 32-stream 145.7 tok/s value is the sum across all requests. Individual-request averages, queueing time and tail delay must be reported alongside total output. This workload cannot establish a safe number of concurrent production users.

03. The unresolved engineering work

Deliberately including failures is part of making this study useful to other engineers.

01 / POLICY BOUNDARY

Retrieved data can override definitions

Some tool-assisted development cases treated observed records as permission to change a canonical rule. Separate tool accuracy from answer-policy adherence.

02 / OUTPUT SAFETY

Identifier masking needs its own gate

A recorded response exposed internal identifiers where a masked or synthetic example was expected. No values are included in this publication.

03 / MODEL SERVING

Thinking without a visible answer

Some nonstandard prompt conditions exhausted tokens in reasoning or produced an empty visible-answer field. Parser and end-of-answer checks are essential.

04 / EVALUATION

Independent holdout not established

The final 134-case set was not scored and has five known verbatim overlaps with training text. It must be cleaned before independent evaluation.

05 / USER EXPERIENCE

Long answers carry high latency

The fixed depth gate completed 8/8 reports but averaged 406.4 seconds each. Answer generation is not proof of answer correctness.

06 / PORTABILITY

Language and response-mode drift

Short-writing responses could become too terse when reasoning was off; some Chinese replies mixed character variants. Prompt and mode matter.

04. How to evaluate more rigorously

A proposed next protocol, not a claim that these steps were already completed.

STEP 01Clean the holdout

Deduplicate exact and near-matching questions before assessing generalization.

STEP 02Split the success criteria

Grade tool choice, final answer, policy boundaries and masking separately.

STEP 03Time the whole journey

Measure TTFT, answer-vs-reasoning tokens, latency and tail behavior.

STEP 04Repeat and independently review

Log variance, cache state and reviewer disagreements rather than a single score.
